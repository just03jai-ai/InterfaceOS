# Color Foundation Approval Checklist

Status: Template — approval remains blocked until every required discipline signs

## Architecture gate

- [ ] Color philosophy and principles are approved.
- [ ] Primitive family and scale strategy is approved.
- [ ] Semantic taxonomy and mapping rules are approved.
- [ ] Light/Dark and future-theme architecture is approved.
- [ ] Open decisions are resolved or have owned, time-bound exclusions.

## Design gate

- [ ] Human Figma exploration is complete.
- [ ] Current baseline and proposed changes are compared.
- [ ] Enterprise dashboard, state, and chart boards are reviewed.
- [ ] Selected visual decisions include rationale and rejected alternatives.
- [ ] Jai Singh records temporary design review without self-approving final release.

## Engineering gate

- [ ] Token feasibility and naming compatibility are approved by an engineering specialist.
- [ ] Aliases, themes, outputs, gamut/fallback, and migration effects are reviewed.
- [ ] Deterministic validations and builds pass from a clean checkout.
- [ ] No unresolved breaking change lacks an ADR and migration plan.

## Accessibility gate

- [ ] An accessibility specialist reviews all declared contrast relationships.
- [ ] Non-color status, focus, selection, disabled, forced-colors, CVD, and chart behavior are approved.
- [ ] Manual evidence supplements automation.
- [ ] Exceptions name the affected users, owner, expiry, and remediation.

## Evidence and governance gate

- [ ] Figma IDs, screenshots, Git/Figma revisions, and checksum are captured.
- [ ] Drift is synchronized with no unresolved Critical/High findings.
- [ ] Evidence manifests and documentation validate.
- [ ] The library remains private until the publishing policy is satisfied.
- [ ] An independent final approver signs the release decision.
