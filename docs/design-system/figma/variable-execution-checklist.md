# Human Figma Variable Execution Checklist

Status: Stage 2 decisions approved; human Figma execution not started

Canonical file: [InterfaceOS — Design System](file-registration.md)

Git token sources are authoritative. Counts below are derived from the Stage 1 source files and must be recalculated after any approved token change. Do not copy resolved values from this document; read the named source file at the reviewed Git revision.

## Preflight rules

- Record the Git revision and verify `pnpm tokens:validate` and `pnpm tokens:build` pass.
- Verify the Figma file, access controls, private-library setting, page/section IDs, and assigned reviewers.
- Create only the five collections accepted by ADR-0004.
- Convert Git dots to Figma `/` groups without renaming segments.
- Set explicit variable scopes. Do not leave unrestricted scope as a convenience default.
- Preserve aliases wherever Figma supports a lossless reference. Never replace an alias with a resolved value.
- Put canonical name, source path, DTCG type/unit, evidence ID, token version, and Git revision in the description or approved structured metadata.
- Stop on any unapproved type conversion, missing alias target, duplicate name, or count mismatch.

## Mode rules

- `Primitive`, `Semantic`, `Responsive`, and `Motion` have no authored modes. Figma's required internal default storage mode is not a product mode.
- `Theme` uses exactly `Light` and `Dark`; names must match the canonical theme contract.
- Semantic color variables alias the stable theme slots. Theme modes alias primitive colors.
- Reduced motion is a semantic alias in `Motion`; it is not a third color-theme mode.
- Responsive references are validation/layout guidance, not device-specific Figma modes.

## Completion rule

The checklist is complete only when every task has a named reviewer, recorded evidence, and either a completed result or an approved time-bound exception. Creating collections or variables alone is not completion.
