# Documentation Standards

## Rules

- Each topic has one canonical owning document; link instead of copying sections.
- State purpose, status, version, owner, scope, decisions, evidence, dependencies, and review date when applicable.
- Separate approved facts from proposals and generated output.
- Use stable artifact IDs and repository-relative links.
- Define acronyms on first use and use controlled terms consistently.
- Examples must be valid, accessible, non-secret, and clearly marked as examples.
- Breaking changes include migration and deprecation guidance.

## Artifact documentation

Applicable specifications cover overview, purpose, preview, variants, sizes, states, properties, tokens, accessibility, interactions, animation, responsive rules, usage, do/don't guidance, examples, related artifacts, code mapping, Storybook mapping, AI metadata, history, owner, and dependencies.

## Review

Authors verify links and schema-backed examples locally. Domain owners review correctness; documentation owners review clarity and structure; accessibility owners review applicable claims. Review evidence is recorded in the artifact manifest.

## Lifecycle

Draft documentation may accompany research and specification. Release documentation is versioned with the artifact and cannot claim approval before the governance gate passes.
